Guide : comprendre et installer un MCP

Le principe

Un serveur MCP expose des outils (functions) que l'agent IA peut appeler : list_boards, create_file, browser_navigate… Le client IA (Devin, Claude, Cursor…) lance le serveur au démarrage et découvre ses outils automatiquement.

Remote vs local

Remote (HTTPS)Local (stdio)
Lancementdéjà hébergé, juste une URLcommande npx/binaire exécutée par le client
Authsouvent OAuth (navigateur) ou clé APIgénéralement aucune — tourne sur votre machine
ExemplesTrello, GitHub, DeepWiki, ExaPlaywright, Memory, Semgrep, Context7

Installer sur Devin

Fusionner dans %APPDATA%\devin\mcp_config.json sous mcpServers :

{
  "mcpServers": {
    "trello": { "url": "https://mcp.trello.com/v1", "transport": "http" },
    "memory": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-memory"] }
  }
}

Redémarrer Devin → le serveur apparaît dans les MCP actifs. Sous Windows, préférer "command": "cmd.exe", "args": ["/c", "npx", "-y", "..."] quand npx n'est pas trouvé.

Pièges rencontrés (vrai vécu)

  • OAuth Trello : le consentement générique échoue → il faut relancer avec les scopes explicites (read:board:trello write:board:trello…)
  • Windows + npx : l'app graphique ne trouve pas toujours npx dans le PATH → utiliser cmd.exe /c npx ou le chemin absolu de l'exécutable
  • Serveur auto-désactivé : un échec de démarrage ajoute "disabled": true à la config — vérifiez-la
  • Chemin absolu requis parfois : ex. Semgrep — semgrep.exe complet plutôt que semgrep

Sécurité

  • Ne jamais commiter de token/secret dans les configs — utiliser des variables d'environnement
  • Un MCP local tourne avec VOS droits : computer-use clique réellement, semgrep lit vos fichiers
  • OAuth = jeton révocable : préférez-le aux clés en dur
