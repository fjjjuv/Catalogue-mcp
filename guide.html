Guide: understanding & installing an MCP

The principle

An MCP server exposes tools (functions) the AI agent can call: list_boards, create_file, browser_navigate… The AI client (Devin, Claude, Cursor…) launches the server at startup and discovers its tools automatically.

Remote vs local

Remote (HTTPS)Local (stdio)
Launchalready hosted, just a URLnpx/binary command run by the client
Authenticationoften OAuth (browser) or API keyusually none — runs on your machine
ExemplesTrello, GitHub, DeepWiki, ExaPlaywright, Memory, Semgrep, Context7

Install on Devin

Merge into %APPDATA%\devin\mcp_config.json under mcpServers:

{
  "mcpServers": {
    "trello": { "url": "https://mcp.trello.com/v1", "transport": "http" },
    "memory": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-memory"] }
  }
}

Restart Devin → the server shows in active MCPs. On Windows prefer cmd.exe /c npx when npx isn't found.

Pitfalls (real experience)

  • Trello OAuth: the generic consent fails → relaunch with explicit scopes (read:board:trello write:board:trello…)
  • Windows + npx: GUI apps don't always find npx in PATH → use cmd.exe /c npx or the binary's absolute path
  • Auto-disabled server: a startup failure adds "disabled": true to the config — check it
  • Absolute path sometimes required: e.g. Semgrep — full semgrep.exe path rather than semgrep

Security

  • Never commit tokens/secrets in configs — use environment variables
  • A local MCP runs with YOUR rights: computer-use really clicks, semgrep reads your files
  • OAuth = revocable token: prefer it over hardcoded keys
